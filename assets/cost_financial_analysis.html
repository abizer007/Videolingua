Why the pipeline is financially efficient

  • Working path converts localization spend into compute, storage, and QA instead of per-minute studio labor.
  • Open-source/local stages reduce recurring API exposure when XTTS, WhisperX, IndicTrans2, and ffmpeg paths are used.
  • Cloud GPU use can be rented per batch, keeping infrastructure variable while preserving the local/offline architecture.

Key Financial Takeaways

  • Compute is small; human QA becomes the main scaling cost.
  • GPU enablement is the highest ROI infrastructure step.
  • Local XTTS keeps vendor spend near zero for supported languages.
  • Paid APIs are useful for gaps, not as the default cost base.

Risks / Assumptions

  • GPU throughput is estimated until a CUDA cloud benchmark exists.
  • Known run used ffmpeg mux, not Wav2Lip or MuseTalk animation.
  • API costs apply only when Sarvam, Hume, ElevenLabs, or Google routes are selected.
  • Language QA and legal review are excluded from infrastructure math.
